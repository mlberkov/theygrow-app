# Enforced invariants — theygrow-app

## Bar

`INVARIANTS.md` is **enforced-only**. An invariant goes here only when a packet enforces it in code — a test, a lint rule, a schema constraint, a runtime guard, or a CI gate. Intent and runtime contract do **not** live here:

- **Intent-level invariants** (what the contract says we will do) live in `AGENTS.md` §2 and §3.
- **Documented runtime behavioral contract** (what the running system must do, before code lands) lives in [`RUNTIME-INVARIANTS.md`](RUNTIME-INVARIANTS.md).

Keeping this file enforced-only prevents it from drifting into a wish list.

## Invariants

### M1-P3-INV-001 — No secrets committed

- **Statement.** No secret or credential material is committed to the repository.
- **Enforced by.** `.pre-commit-config.yaml` (gitleaks hook) and `.github/workflows/ci.yml` (runs the gitleaks hook via `pre-commit run --all-files`, with full history fetched).
- **Landed in.** M1-P3.
- **Scope.** Covers tracked content and commit history reachable in CI. Public, non-secret identifiers (e.g. the GA4 Measurement ID, the GCP project id / region) are not secrets; should the scanner ever flag one, the remedy is an exact non-secret allowlist entry in a `.gitleaks.toml` at the repository root. No such file exists today and nothing has been allowlisted — the hook runs on its stock ruleset. Genuine secrets are never allowlisted.

### M1-P3-INV-002 — Contract integrity

- **Statement.** Within the contract + spine documents, three conditions hold: (a) superseded stack names do not reappear as active targets; (b) the legacy pre-rename repository directory name does not appear; (c) live-infra identifiers stay confined to `docs/RUNBOOK.md`.
- **Enforced by.** `scripts/check-contract-integrity.sh`, wired into `.pre-commit-config.yaml` (local hook) and `.github/workflows/ci.yml`. The script holds the authoritative match patterns for all three checks; they are intentionally not restated inline here, since this file is itself within the scanned corpus.
- **Landed in.** M1-P3.
- **Scope.** Governs the contract + spine corpus: `AGENTS.md`, `CLAUDE.md`, `docs/INVARIANTS.md`, `docs/RUNTIME-INVARIANTS.md`, `docs/execution-map.md`, `docs/RUNBOOK.md`, `docs/product/BuildPlan.md`, `docs/product/TechSpec.md`, `.cursor/rules/masterplan.mdc`. Live-deploy paths are out of scope — they carry live-infra identifiers as operational reality. Historical artifacts (`docs/decision-log.md`, `data/mvp_masterplan.md`) are exempt — they record the superseded plan by design. This promotes the previously-manual P1/P2 negative-checks into an enforced gate. P4 tightened check (b) to a strict ban by removing its interim pairing exception once the residual naming sweep was complete.

### M2-P2-INV-001 — No child PII in logs / telemetry (forward guard)

- **Statement.** No known child-PII field (child name, diary text, birthdate / dob) is emitted through the logging boundary: known PII field names carried on a log record are redacted to `[REDACTED]` before any handler formats the record.
- **Enforced by.** `api/theygrow_api/logging.py` (`PiiRedactionFilter`) + `api/tests/test_logging_redaction.py`, run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M2-P2.
- **Scope.** A **forward guard**: it establishes telemetry/redaction discipline from the first byte of backend code (AGENTS.md §4). At P2 there is **no live child-PII data path** — those arrive at M3 — so this covers the logging-boundary redaction *mechanism* and its test, not end-to-end coverage over live child data; coverage extends as data paths land (M3 → M5). It governs known structured PII field names only, not free-text message bodies.

### M4-P1-INV-001 — Sparse FTS leg is index-backed

- **Statement.** The sparse (lexical) retrieval leg matches against a generated, DB-maintained `tsvector` (`event_chunks.chunk_text_tsv`, `to_tsvector('simple', chunk_text)`) backed by a GIN index, and is community-scoped — a query never crosses community boundaries.
- **Enforced by.** `api/alembic/versions/0002_notes_event_chunks.py` (the GENERATED STORED column + `idx_event_chunks_chunk_text_tsv` GIN index) + `api/tests/test_search_repository.py` (match, `ts_rank_cd` ordering, community scoping, inclusive `note_date` range, empty-query / non-positive-limit short-circuits), run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P1.
- **Scope.** Covers the sparse leg's **mechanics** only. It does **not** establish Russian lexical recall adequacy: the `'simple'` config does no morphological stemming (the documented limitation and named port-out trigger, `M4-DL-001`); recall is measured at the M4-close mini-eval, not here. The dense leg, RRF fusion, and the episodic-eligibility filter are out of scope (M4-P2/P3).

### M4-P2-INV-001 — Per-chunk embedding is dimension-pinned and drift-guarded

- **Statement.** The dense leg's vector is per-chunk on `event_chunks.embedding`, typed `vector(1536)` as a frozen literal in the migration DDL; the schema-bound `embedding_dimension` surface value is linked to the live column type by a drift guard (a surface bump without a matching migration fails). ### M4-P2-INV-002 — Embeddings backfill is fail-closed without the ZDR clearance gate

- **Statement.** The offline embeddings backfill sends no `chunk_text` **out of the perimeter** and writes nothing unless the operator-set `embedder_privacy_cleared` flag (the ZDR + DPA + EU-residency clearance) is set — and, on the real path, the embedder endpoint/key are present. With the gate unmet the run refuses before any provider call or DB write (zero provider calls, zero writes). The gate is scoped to **egress**: it applies to the real provider path and to any injected provider that does not structurally declare zero egress, and is skipped only for an in-perimeter provider (`performs_no_egress is True`), which removes the third-party surface rather than satisfying its clearance. That check is itself fail-closed — an absent or non-`True` declaration reads as egressing — so the narrowing cannot become a bypass by omission.
- **Enforced by.** `api/theygrow_api/embeddings_backfill.py` (`_ensure_embedder_cleared` / `_build_provider`, raising `EmbedderNotReady` before any text egress) + `api/theygrow_api/ports/provider.py` (`performs_no_egress`, the fail-closed declaration predicate — private to the backfill until A2-P3 hoisted it beside the two ports it now serves) + `api/theygrow_api/config.py` (the default-false `embedder_privacy_cleared` flag) + `api/tests/test_embeddings_backfill.py` (`test_fail_closed_when_uncleared`, `test_fail_closed_when_unconfigured`) + `api/tests/test_seed_staging.py` (`test_unmarked_provider_still_gated_when_uncleared`, `test_truthy_declaration_is_not_enough`), run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P2 (statement amended A2-P2: the gate restated as egress-scoped, with the in-perimeter exemption and its fail-closed default — `L2-DL-002`; amended A2-P3: the declaration predicate moved to `ports/provider.py`, and the same egress scoping was extended to the READ path — `L2-DL-003`, `L2-P3-INV-001`).
- **Scope.** A structural §4 gate over the one permitted child-text egress (ADR-011 §1). It governs the offline backfill path; the read path's query-embedding gate is the same mechanism and is stated at `L2-P3-INV-001` (there is still no live *request* path that embeds — chat is M5). It binds the gate mechanism, not the external provider's actual ZDR posture (an operational precondition the owner clears). Since A2-P2 it also does not bind what an in-perimeter provider computes — only that one which claims the exemption has declared it structurally; that a declaring provider genuinely performs no I/O is a property of that provider's code, not something this gate can verify.

### M4-P2-INV-003 — Embeddings backfill is idempotent and index-after-population

- **Statement.** The backfill embeds only `pending` (and, unless `--no-retry-failed`, `failed`) chunks and skips `ready` ones, so a re-run over a fully-embedded corpus is a no-op (no duplicate writes, no extra provider calls); a provider error marks the batch `failed` for retry, never a partial vector. The HNSW index is built by the backfill AFTER bulk population, not by the migration.
- **Enforced by.** `api/theygrow_api/embeddings_backfill.py` (status-driven selection; `CREATE INDEX IF NOT EXISTS` after population) + `api/tests/test_embeddings_backfill.py` (`test_backfill_is_idempotent`, `test_backfill_marks_failed_then_retries`, `test_backfill_builds_hnsw_index_after_population`) + `api/tests/test_embedding_schema.py` (`test_migration_alone_builds_no_hnsw_index`), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P2.
- **Scope.** Covers the offline backfill pass over already-derived chunks. Embedding quality / vector correctness beyond dimension is out of scope; the injected fake provider exercises mechanics, not a live embedder.

### M4-P4-INV-001 — Answer synthesis is fail-closed without the answers ZDR clearance gate

- **Statement.** The grounded-ask service sends family context to the answers LLM and synthesizes an answer ONLY when `answers_privacy_cleared` is set; uncleared (or endpoint/key missing) it raises `AnswersNotReady` before any provider call or text egress, making ZERO answers-provider calls (ADR-014, per-egress clearance; the answers LLM is a distinct residency surface from the embedder, so the embedder's clearance does not clear it). That check is fail-closed — an absent or non-`True` declaration reads as egressing. **The narrowing grants no clearance**: `answers_privacy_cleared` stays default-false, the real path is unchanged, and owner clearance for the answers residency surface remains an open prerequisite.
- **Enforced by.** `api/theygrow_api/services/query_service.py` (`_ensure_answers_cleared` runs first, before `retrieve`/build/call) + `api/tests/test_query_service.py` (`test_answers_fail_closed_when_uncleared_zero_calls`, asserting `AnswersNotReady` and zero recorded provider calls), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P4 (statement and scope amended A2-P3: the gate restated as egress-scoped, with the in-perimeter exemption and its fail-closed default; the narrowing grants no clearance — `L2-DL-003`, `L2-P3-INV-001`).
- **Scope.** Covers the answers/chat egress only (the second §4 surface); the query-embedding egress stays gated by `embedder_privacy_cleared` inside `retrieve()` (`L2-P3-INV-001` / ADR-011). It is a structural refusal (loud no-op), not a content degradation. Since A2-P3 it also does not bind what an in-perimeter answers provider computes — only that one claiming the exemption declared it structurally; that a declaring provider genuinely opens no socket is a property of that provider's code, not something this gate can verify.

### M4-P4-INV-002 — Grounded answers are closed-corpus or honestly degraded

- **Statement.** A non-`None` `answer_text` is produced ONLY from retrieved + cited family episodic memory — never a parametric/model or web fallback. Three independent edges enforce this: the prompt carries only retrieved `chunk_text`; the parser rejects any `cited_chunk_id` absent from the assembled context (a fabricated citation → suppressed `parse_failure`); and a pre-provider grounding gate (`grounding_min_segments`) returns an honest `no_evidence` result with ZERO provider calls below the bar. A model-declared `no_evidence` (present-but-irrelevant context) also suppresses the answer.
- **Enforced by.** `api/theygrow_api/services/context_assembler.py` (`parse_structured_answer` citation grounding) + `api/theygrow_api/services/query_service.py` (the grounding gate + degradation contours) + `api/tests/test_query_service.py` (`test_fabricated_citation_is_parse_failure`, `test_no_context_degrades_with_zero_answers_calls`, `test_present_but_irrelevant_context_llm_declares_no_evidence`), run by `pytest api`.
- **Landed in.** M4-P4.
- **Scope.** Family episodic memory is the only grounded source at M4 (canon/KB is M5, out of perimeter), so provenance is family-observation lineage only. Grounded-but-uncertain answers are RETURNED with an honesty flag (ADR-015), not suppressed — they remain closed-corpus (cited retrieved context). These are deterministic seam-mechanics guarantees with injected fakes; real retrieval recall / grounding QUALITY is the M4-CLOSE eval, not enforced here.

### A1-P1-INV-001 — The spa-split refactor is gated by a three-level parity suite

- **Statement.** Every A1 `spa-split` packet must pass an automated three-level parity threshold against committed baselines of the pre-split app: **(a)** DOM-snapshot equality for `header`, `#mainTable` (head, body digest, and full-body hash), `footer.control-footer`, `#zpdEmptyState` and the four modals across four boot states at two viewports, plus a SHA-256 per skill-modal body for all 174 skills; **(b)** pixel-equal screenshots of those surfaces at 1280×800 and 412×760, captured on a platform fixed by a pinned browser container rather than by the CI runner image; **(c)** behavioural smoke over the main tick → ZPD-recompute → persist → reload loop, the no-profile honest-degradation refusal, the activity→skill deep link and modal stack, service-worker registration / offline boot from precache / the PWA update flow, and the kb-load error path. Baselines are never written implicitly: `updateSnapshots: 'none'` makes a missing or changed baseline fail, and only an explicit `--update-snapshots` run may rewrite one. *(Namespace note: id follows the `A1-P{k}` packet namespace of the spa-split milestone, mirroring the `VDK-P3-INV-001` precedent for a non-`M{N}` namespace; the "Entry format" footer below is intentionally left unedited, matching how the decision-log treats its non-spine namespaces.)*

It asserts that behaviour did not change; it does not assert that the behaviour it froze is *correct* (the fixed state it baselines is `A0-DL-001` + `A1-DL-001`). The suite is dev/CI-only and is excluded from both the production image and the Docker build context, so it constrains no runtime behaviour.

### A1-P3-INV-001 — The image ships everything the shell references, and the shell and the precache agree

- **Statement.** Two directions are machine-asserted on every CI run against the **real** `app/Dockerfile` `COPY` list: **(a)** every same-origin asset referenced by a shipped HTML shell, and every entry of `OFFLINE_URLS` in `app/sw.js`, resolves to a path the image ships **and** that exists on disk; **(b)** every same-origin asset referenced by a shipped shell is **also** precached by name in `OFFLINE_URLS`. Direction (a) exists because `app/Dockerfile` has no wildcard `COPY` while the parity server serves from the `app/` directory on disk — a forgotten `COPY` therefore passes the whole suite and 404s only in production. Direction (b) exists because module-mount bumps are copy-forward (`A1-DL-004`): both the old and the new mount version stay shipped, so (a) alone would stay green while `index.html` pointed at one version and `OFFLINE_URLS` still listed the other. The `COPY` parser fails **closed** — any form it does not fully understand throws, since a skipped line is a loud false negative while a mis-parsed destination is a silent false positive.
- **Enforced by.** `app/tests/delivery-contract.spec.js` (the `ship list — app/Dockerfile ships everything the shell needs` describe-block), run in the `contract` project of `app/playwright.config.js` via `scripts/parity-suite.sh` — invoked as the `parity` job in `.github/workflows/ci.yml`. Sources are the real `app/Dockerfile`, `app/sw.js` (`OFFLINE_URLS` read textually, with a loud throw on no-match, because `app/sw.js` calls `self.addEventListener` and cannot be `require()`d), `app/manifest.json` (`icons[].src`), and the shipped HTML shells `app/index.html` and `app/offline.html`.
- **Landed in.** A1-P3.
- **Scope.** Covers assets referenced from HTML attributes (`href=`/`src=` values beginning with `/`), manifest icon sources, and the precache list — since A1-P6 that surface includes the `<link rel="modulepreload">` delivery hints, so every hinted module is asserted shipped-and-precached as a shell reference in its own right, independently of the import walk that also reaches it. It does **not** cover: assets referenced only from JavaScript string literals — `fetch('/kb-v1.json')` in the shell is covered incidentally, via `OFFLINE_URLS`, and a future runtime-fetched asset that is not precached would be invisible; `url()` / `@import` references inside CSS (there are none today); `app/.dockerignore`, which the guard does not consult, so a future ignore pattern matching `m/` would make `COPY m/` ship nothing with this guard still green; and production `Content-Type`, which comes from the base image's `mime.types` and is observed only by the promotion-smoke curl in `docs/RUNBOOK.md`. The copy-forward / never-overwrite half of the `A1-DL-004` mount contract is a documented owner procedure, **not** a gate — nothing here can detect bytes changing at an already-published URL within one commit.

### A1-P4-INV-001 — The shipped module import graph is shipped and precached, transitively

- **Statement.** Every module the shell's `<script type="module">` entries import, transitively, resolves to a path the image ships **and** that is precached by name in `OFFLINE_URLS`. This extends `A1-P3-INV-001` past the HTML attribute surface: the walk is rooted at the shell's **execution** entries — its `<script type="module" src>` values, `/m/v1/app.js` and `/m/v1/sw-register.js` — and every other module (`core/` since A1-P4, `surfaces/` since A1-P5) is reachable only through an `import` statement, so both of that invariant's directions would stay green while a module was absent from the `app/Dockerfile` `COPY` list (a production 404 that no test sees, because the parity server serves from disk) or from `OFFLINE_URLS` (a broken import graph on the first offline boot, because `cache.addAll` never fetched it). Since A1-P6 the shell additionally **names** each non-entry module in a `<link rel="modulepreload">` hint. A hint is a delivery instruction, not an evaluation root — `modulepreload` fetches and compiles, it never evaluates — so hints are deliberately excluded from the walk's roots: rooting it at every `.js` the shell names would make `moduleDependencies()` delete the entire graph as "entries" and silently reduce this invariant to **zero** assertions with CI still green (`A1-DL-006` (g), `A1-DL-007` (d)). The walker fails **closed** at both ends: a dynamic `import()`, an indented module statement, or a bare specifier throws rather than being silently skipped, since the app is buildless and has no import map to resolve one; and a same-origin `<script src>` that is not `type="module"` throws rather than being silently dropped from the roots or silently added to them.
- **Enforced by.** `app/tests/delivery-contract.spec.js` (`htmlModuleEntries` / `moduleSpecifiers` / `resolveSpecifier` / `moduleDependencies`, asserted in the `ship list — app/Dockerfile ships everything the shell needs` describe-block), run in the `contract` project of `app/playwright.config.js` via `scripts/parity-suite.sh` — invoked as the `parity` job in `.github/workflows/ci.yml`. Sources are the real `app/Dockerfile`, `app/sw.js` and the shipped module files on disk.
- **Landed in.** A1-P4 (statement amended A1-P5: the graph reached this way now includes `surfaces/`; amended A1-P6: the walk's roots stated explicitly as the shell's `<script type="module">` entries — two of them since A1-P3, not the one the earlier wording claimed — with `modulepreload` hints excluded as roots).
- **Scope.** Covers **static** `import` / `export … from` specifiers in shipped JavaScript modules reached from a shipped HTML shell. It does **not** cover: dynamic `import()` (rejected loudly rather than followed — the parity suite's own test-seam import lives in dev/CI code, which this walker never reads); CSS `@import` / `url()` (there are none today, same gap as `A1-P3-INV-001`); assets fetched from JS string literals; import correctness beyond existence — a module that ships and is precached but throws on evaluation is the parity suite's business, not this guard's; or whether the `modulepreload` hint set agrees with the graph this walk produces, which is `A1-P6-INV-001`'s business and not this one's.

### A1-P6-INV-001 — The module delivery hints and the shipped import graph are the same set

- **Statement.** The set of `<link rel="modulepreload">` hrefs in the shipped HTML shells equals, exactly and in both directions, the transitive import graph `A1-P4-INV-001` walks from the shell's `<script type="module">` entries: **(a)** every hint names a module that walk reaches — a hint the graph no longer contains is a fetch nothing evaluates, which is what a copy-forward mount bump or a removed module would leave behind; **(b)** every module that walk reaches carries a hint — an unhinted module is discovered only after its importer parses, which costs the same-origin round trip A1-P6 removed and which nothing else in this repo would ever notice. Direction (b) is the load-bearing one: it makes the hint list a machine-checked consequence of the graph rather than a hand-maintained list that rots on the next extraction. The hints are same-origin absolute paths and are additionally asserted shipped-and-precached as shell references by `A1-P3-INV-001`, so a hint pointing at an unshipped path fails there.
- **Enforced by.** `app/tests/delivery-contract.spec.js` (`htmlPreloadHints`, plus the `PRELOAD_HINTS` ↔ `MODULE_DEPS` set-equality loops and the fail-closed classifier asserting every same-origin `.js` the shell names is either a module entry or a hint), run in the `contract` project of `app/playwright.config.js` via `scripts/parity-suite.sh` — invoked as the `parity` job in `.github/workflows/ci.yml`. Sources are the shipped HTML shells `app/index.html` and `app/offline.html` and the shipped module files on disk.
- **Landed in.** A1-P6.
- **Scope.** Covers set membership only: which modules are hinted. It does **not** cover: hint *ordering* or placement in the document (both affect fetch scheduling and neither is asserted); whether a hint actually improved anything (a waterfall measurement is a packet-time argument in `A1-DL-007`, not a gate — nothing in CI measures delivery timing); `rel="preload"` / `prefetch` / `preconnect` of any kind (there are none today, and this guard would not see them); hints for cross-origin modules (rejected loudly instead — the mount is version-in-path and a hint must track it); or whether the browser honours the hint at all, which varies by engine and is outside every level of the parity suite.

### L2-P2-INV-001 — The staging seed is fail-closed on the target-database marker

- **Statement.** The staging seed writes only to a database carrying the staging marker, asserted independently in two places: the database name parsed from `DATABASE_URL` **before any connection is opened**, and `SELECT current_database()` on the connected server **before any write**. Both compare against an allowlist of exactly one name, so a production name, a near-miss name and an absent name all refuse — the guard fails closed in both directions rather than blocking a known-bad list. The two layers exist because the first trusts a string while only the second asks the server, which is what catches a libpq `host=`/socket override or a pooler landing the connection somewhere the URL did not name. The refusal names the database only, never the connection string (§4). *(Namespace note: id follows the `L2-P{k}` packet namespace of the l2-staging milestone, mirroring the `VDK-P3-INV-001` / `A1-P1-INV-001` precedent for a non-`M{N}` namespace; the "Entry format" footer below is intentionally left unedited, matching how the decision-log treats its non-spine namespaces.)*
- **Enforced by.** `api/theygrow_api/seed_staging.py` (`ensure_staging_target` / `ensure_staging_server` against the `STAGING_DATABASE_NAME` allowlist, raising `NotStagingTarget`; the whole seed runs in one transaction so a refusal leaves the target untouched) + `api/tests/test_seed_staging.py` (`test_url_guard_refuses_anything_but_the_marker`, `test_seed_refuses_before_touching_the_corpus_when_url_is_not_staging`, `test_server_guard_refuses_when_url_and_server_disagree`, `test_url_guard_refusal_does_not_echo_the_connection_string`), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** A2-P2.
- **Scope.** Covers which database the seed may write to, and that a refusal writes nothing. It does **not** make the corpus itself safe — that staging holds no real family data is an authorship property of the corpus (see `api/corpus/staging/README.md`), unprovable by any test and deliberately not claimed here. It does not govern the other CLIs: `theygrow-import-export`, `theygrow-rederive` and `theygrow-embed` remain unguarded and will still act on whatever `DATABASE_URL` names. Nothing here constrains production; it constrains this seed.

### L2-P2-INV-002 — The clearance gate's default is egress, and the staging seed crosses no third-party boundary

- **Statement.** Two halves, the first load-bearing. **(a)** An embedding provider is treated as egressing unless it structurally declares otherwise: a missing declaration, or any value that is not exactly `True`, is gated by `embedder_privacy_cleared` exactly as before the A2-P2 narrowing — so the exemption cannot be acquired by omission, by a truthy stand-in, or by a provider that simply forgot. **(b)** Given that default, the staging seed embeds through an in-perimeter provider (`LocalDeterministicEmbeddingProvider`, no network client, no I/O) and therefore populates the dense leg while both clearance flags stay unset, making zero third-party provider calls (ADR-020). Clearance is per-egress-surface (ADR-014); an in-perimeter embedder removes the surface rather than satisfying its clearance. *(Namespace note: as `L2-P2-INV-001`.)*
- **Enforced by.** `api/theygrow_api/ports/provider.py` (`performs_no_egress`, defaulting to gated — in `embeddings_backfill.py` until A2-P3 moved it beside the ports) + `api/theygrow_api/adapters/embeddings/local_deterministic.py` (the declaring provider) + `api/theygrow_api/seed_staging.py` (which injects it) + `api/tests/test_seed_staging.py` (`test_unmarked_provider_still_gated_when_uncleared` and `test_truthy_declaration_is_not_enough` for half (a); `test_seed_populates_the_contour_with_zero_third_party_calls` and `test_in_perimeter_provider_runs_with_clearance_unset` for half (b)), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** A2-P2 (predicate relocated A2-P3 — `L2-DL-003`; semantics byte-for-byte unchanged).
- **Scope.** Covers the gate's default disposition and the seed's provider wiring. It does **not** verify that a declaring provider truly performs no I/O — the declaration is trusted, and only code review keeps it honest; the test asserts the seed's calls all reach the injected in-perimeter provider, not that no socket exists anywhere. It says nothing about embedding **quality**: the local provider's similarity is authored from `concepts.json`, so it exercises the dense leg's plumbing and makes a semantic-only eval case authorable, and transfers no recall claim to the real embedder.

### L2-P3-INV-001 — The read-path clearance gates default to egress, and the eval crosses no third-party boundary

- **Statement.** Two halves, the first load-bearing. **(a)** On the READ path — the query embedding inside `retrieve()` and the answers egress inside `answer_query()` — a provider is treated as egressing unless it structurally declares otherwise: a missing declaration, or any value that is not exactly `True`, is gated by `embedder_privacy_cleared` / `answers_privacy_cleared` exactly as before the A2-P3 narrowing, so the exemption cannot be acquired by omission, by a truthy stand-in, or by a provider that simply forgot. **(b)** Given that default, the eval pipeline drives both seams through in-perimeter providers (`LocalDeterministicEmbeddingProvider`, `ScriptedAnswersProvider`) and therefore runs the whole labeled query set while BOTH clearance flags stay unset, making zero third-party provider calls (ADR-020). Clearance is per-egress-surface (ADR-014); an in-perimeter provider removes the surface rather than satisfying it, so **nothing here grants a clearance** — `answers_privacy_cleared` in particular remains default-false and an open owner prerequisite. *(Namespace note: as `L2-P2-INV-001`.)*
- **Enforced by.** `api/theygrow_api/ports/provider.py` (`performs_no_egress`, defaulting to gated) + `api/theygrow_api/services/retrieval.py` and `api/theygrow_api/services/query_service.py` (the two narrowed gate call sites; the answers provider is still built AFTER the grounding gate) + `api/theygrow_api/adapters/embeddings/local_deterministic.py` and `api/theygrow_api/adapters/answers/local_scripted.py` (the declaring providers) + `api/tests/test_retrieval.py` (`test_retrieve_fail_closed_when_uncleared`, `test_retrieve_truthy_declaration_is_not_enough` for half (a); `test_retrieve_in_perimeter_provider_runs_with_clearance_unset` for half (b)) + `api/tests/test_query_service.py` (`test_answers_fail_closed_when_uncleared_zero_calls`, `test_truthy_answers_declaration_is_not_enough`, `test_in_perimeter_answers_provider_runs_with_clearance_unset`) + `api/tests/test_evals.py` (`test_labeled_set_passes_on_the_seeded_contour`, which runs the whole set with both flags unset), run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** A2-P3.
- **Scope.** Covers the two read-path gates' default disposition and the eval's provider wiring. It does **not** verify that a declaring provider truly performs no I/O — the declaration is trusted, and only code review keeps it honest. It says nothing about retrieval or answer **quality**: the local embedder's similarity is authored from `concepts.json` and the answers provider is a policy over the prompt, so both exercise plumbing and transfer no recall or faithfulness claim to the real providers.

### L2-P3-INV-002 — The eval gates on a recorded, per-case expectation and reports §4-safely

- **Statement.** Three halves. **(a)** The eval refuses to run at all unless the connected database carries the staging marker (both layers, reused from the seed), holds exactly the chunk and community counts the corpus on disk implies, and returns a stored vector that agrees with the run's own lexicon — so an empty, stale or wrong contour is a named refusal with its own exit code, never a vacuous pass on the three case classes that assert ABSENCE. **(b)** The gate is binary and structural: every labeled case must meet the expectation recorded beside it in `evals/queries.py`, and any cross-community or draft-route leak fails the run. There is no pass-rate threshold and no separately recorded baseline — the labeled set IS the baseline, and no environment variable can lower the bar. **(c)** The scorecard artifact and every log line carry case ids, bounded check names, counts and timings only: never query text, never chunk text, never a `community_id`, and never a `chunk_id` (a synthetic id still names its community by substring). *(Namespace note: as `L2-P2-INV-001`.)*
- **Enforced by.** `api/theygrow_api/evals/runner.py` (`check_contour`, raising `ContourNotReady` before any case; exit `2` for cannot-run vs `1` for case failure) + `api/theygrow_api/evals/queries.py` (the frozen set + `LABELED_SET_VERSION`) + `api/theygrow_api/evals/scorecard.py` (`Scorecard.ok`, `to_json_document`) + `api/tests/test_evals.py` (`test_eval_refuses_an_unseeded_contour_before_running_a_case`, `test_eval_refuses_when_stored_vectors_disagree_with_the_lexicon` for half (a); `test_labeled_set_passes_on_the_seeded_contour`, `test_scorecard_is_not_ok_when_a_case_failed` for half (b); `test_scorecard_carries_no_community_id_chunk_id_or_text`, `test_scorecard_uses_no_banned_metric_name` for half (c)) + `api/tests/test_seed_staging.py` (`test_corpus_created_at_is_unique_per_source_message`, the corpus property the legs' tiebreak needs for run-to-run stability), run by `pytest api` in `.github/workflows/ci.yml` and by the `eval` job in the same workflow.
- **Landed in.** A2-P3.
- **Scope.** Covers what the gate refuses, what it requires of each case, and what the artifact may carry. It covers **contract conformance on a fixed synthetic corpus** — retrieval fusion, note-only eligibility, community scoping, the grounding gate, honest degradation — and explicitly **not** Russian lexical recall, embedder semantic quality, or answer faithfulness: the corpus is authored, the embedder's similarity is authored, and the answers provider is our own policy. Those measurements are the M4-CLOSE mini-eval against the real corpus with cleared real providers, and nothing this invariant enforces bears on the `M4-DL-001` or `M4-DL-004` port-out triggers. It also does not make the `/api` promotion precondition a mechanism: `docs/RUNBOOK.md` states the eval run as an owner convention, and nothing reads its exit code on the way to promotion.

## Entry format (for future entries)

- **Id.** `M{N}-P{k}-INV-{NNN}` — `N` is the milestone number, `k` is the packet number within the milestone, `NNN` is zero-padded sequence within the packet (`001`, `002`, …).
- **Required fields.**
  - **Statement.** The invariant in one sentence.
  - **Enforced by.** File path(s) of the enforcing artifact — test, lint rule, schema constraint, runtime guard, or CI workflow.
  - **Landed in.** Packet id + commit SHA where enforcement was introduced.
  - **Scope.** What the invariant covers, and explicitly what it does not.
