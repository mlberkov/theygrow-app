# Enforced invariants — theygrow-app

## Bar

`INVARIANTS.md` is **enforced-only**. An invariant goes here only when a packet enforces it in code — a test, a lint rule, a schema constraint, a runtime guard, or a CI gate. Intent and runtime contract do **not** live here:

- **Intent-level invariants** (what the contract says we will do) live in `AGENTS.md` §2 and §3.
- **Documented runtime behavioral contract** (what the running system must do, before code lands) lives in [`RUNTIME-INVARIANTS.md`](RUNTIME-INVARIANTS.md).

Keeping this file enforced-only prevents it from drifting into a wish list.

## Invariants

### M1-P3-INV-001 — No secrets committed

- **Statement.** No secret or credential material is committed to the repository.
- **Enforced by.** `.pre-commit-config.yaml` (gitleaks hook) and `.github/workflows/ci.yml` (runs the gitleaks hook via `pre-commit run --all-files`, with full history fetched).
- **Landed in.** M1-P3.
- **Scope.** Covers tracked content and commit history reachable in CI. Public, non-secret identifiers (e.g. the GA4 Measurement ID, the GCP project id / region) are not secrets; should the scanner ever flag one, the remedy is an exact non-secret allowlist entry in a `.gitleaks.toml` at the repository root. No such file exists today and nothing has been allowlisted — the hook runs on its stock ruleset. Genuine secrets are never allowlisted.

### M1-P3-INV-002 — Contract integrity

- **Statement.** Within the contract + spine documents, three conditions hold: (a) superseded stack names do not reappear as active targets; (b) the legacy pre-rename repository directory name does not appear; (c) live-infra identifiers stay confined to `docs/RUNBOOK.md`.
- **Enforced by.** `scripts/check-contract-integrity.sh`, wired into `.pre-commit-config.yaml` (local hook) and `.github/workflows/ci.yml`. The script holds the authoritative match patterns for all three checks; they are intentionally not restated inline here, since this file is itself within the scanned corpus.
- **Landed in.** M1-P3.
- **Scope.** Governs the contract + spine corpus: `AGENTS.md`, `CLAUDE.md`, `docs/INVARIANTS.md`, `docs/RUNTIME-INVARIANTS.md`, `docs/execution-map.md`, `docs/RUNBOOK.md`, `docs/product/BuildPlan.md`, `docs/product/TechSpec.md`, `.cursor/rules/masterplan.mdc`. Live-deploy paths are out of scope — they carry live-infra identifiers as operational reality. Historical artifacts (`docs/decision-log.md`, `data/mvp_masterplan.md`) are exempt — they record the superseded plan by design. This promotes the previously-manual P1/P2 negative-checks into an enforced gate. P4 tightened check (b) to a strict ban by removing its interim pairing exception once the residual naming sweep was complete.

### M2-P2-INV-001 — No child PII in logs / telemetry (forward guard)

- **Statement.** No known child-PII field (child name, diary text, birthdate / dob) is emitted through the logging boundary: known PII field names carried on a log record are redacted to `[REDACTED]` before any handler formats the record.
- **Enforced by.** `api/theygrow_api/logging.py` (`PiiRedactionFilter`) + `api/tests/test_logging_redaction.py`, run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M2-P2.
- **Scope.** A **forward guard**: it establishes telemetry/redaction discipline from the first byte of backend code (AGENTS.md §4). At P2 there is **no live child-PII data path** — those arrive at M3 — so this covers the logging-boundary redaction *mechanism* and its test, not end-to-end coverage over live child data; coverage extends as data paths land (M3 → M5). It governs known structured PII field names only, not free-text message bodies.

### M4-P1-INV-001 — Sparse FTS leg is index-backed

- **Statement.** The sparse (lexical) retrieval leg matches against a generated, DB-maintained `tsvector` (`event_chunks.chunk_text_tsv`, `to_tsvector('simple', chunk_text)`) backed by a GIN index, and is community-scoped — a query never crosses community boundaries.

- **Landed in.** M4-P1.
- **Scope.** Covers the sparse leg's **mechanics** only. It does **not** establish Russian lexical recall adequacy: the `'simple'` config does no morphological stemming (the documented limitation and named port-out trigger, `M4-DL-001`); recall is measured at the M4-close mini-eval, not here. The dense leg, RRF fusion, and the episodic-eligibility filter are out of scope (M4-P2/P3).

### M4-P2-INV-002 — Embeddings backfill is fail-closed without the ZDR clearance gate

- **Statement.** The offline embeddings backfill sends no `chunk_text` **out of the perimeter** and writes nothing unless the operator-set `embedder_privacy_cleared` flag (the ZDR + DPA + EU-residency clearance) is set — and, on the real path, the embedder endpoint/key are present. With the gate unmet the run refuses before any provider call or DB write (zero provider calls, zero writes). The gate is scoped to **egress**: it applies to the real provider path and to any injected provider that does not structurally declare zero egress, and is skipped only for an in-perimeter provider (`performs_no_egress is True`), which removes the third-party surface rather than satisfying its clearance. That check is itself fail-closed — an absent or non-`True` declaration reads as egressing — so the narrowing cannot become a bypass by omission.
- **Enforced by.** `api/theygrow_api/embeddings_backfill.py` (`_ensure_embedder_cleared` / `_build_provider`, raising `EmbedderNotReady` before any text egress) + `api/theygrow_api/ports/provider.py` (`performs_no_egress`, the fail-closed declaration predicate — private to the backfill until A2-P3 hoisted it beside the two ports it now serves) + `api/theygrow_api/config.py` (the default-false `embedder_privacy_cleared` flag) + `api/tests/test_embeddings_backfill.py` (`test_fail_closed_when_uncleared`, `test_fail_closed_when_unconfigured`) + `api/tests/test_seed_staging.py` (`test_unmarked_provider_still_gated_when_uncleared`, `test_truthy_declaration_is_not_enough`), run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P2 (statement amended A2-P2: the gate restated as egress-scoped, with the in-perimeter exemption and its fail-closed default — `L2-DL-002`; amended A2-P3: the declaration predicate moved to `ports/provider.py`, and the same egress scoping was extended to the READ path — `L2-DL-003`, `L2-P3-INV-001`).
- **Scope.** A structural §4 gate over the one permitted child-text egress (ADR-011 §1). It governs the offline backfill path; the read path's query-embedding gate is the same mechanism and is stated at `L2-P3-INV-001` (there is still no live *request* path that embeds — chat is M5). It binds the gate mechanism, not the external provider's actual ZDR posture (an operational precondition the owner clears). Since A2-P2 it also does not bind what an in-perimeter provider computes — only that one which claims the exemption has declared it structurally; that a declaring provider genuinely performs no I/O is a property of that provider's code, not something this gate can verify.

### M4-P2-INV-003 — Embeddings backfill is idempotent and index-after-population

- **Statement.** The backfill embeds only `pending` (and, unless `--no-retry-failed`, `failed`) chunks and skips `ready` ones, so a re-run over a fully-embedded corpus is a no-op (no duplicate writes, no extra provider calls); a provider error marks the batch `failed` for retry, never a partial vector. The HNSW index is built by the backfill AFTER bulk population, not by the migration.
- **Enforced by.** `api/theygrow_api/embeddings_backfill.py` (status-driven selection; `CREATE INDEX IF NOT EXISTS` after population) + `api/tests/test_embeddings_backfill.py` (`test_backfill_is_idempotent`, `test_backfill_marks_failed_then_retries`, `test_backfill_builds_hnsw_index_after_population`) + `api/tests/test_embedding_schema.py` (`test_migration_alone_builds_no_hnsw_index`), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P2.
- **Scope.** Covers the offline backfill pass over already-derived chunks. Embedding quality / vector correctness beyond dimension is out of scope; the injected fake provider exercises mechanics, not a live embedder.

### M4-P4-INV-001 — Answer synthesis is fail-closed without the answers ZDR clearance gate

- **Statement.** The grounded-ask service sends family context to the answers LLM and synthesizes an answer ONLY when `answers_privacy_cleared` is set; uncleared (or endpoint/key missing) it raises `AnswersNotReady` before any provider call or text egress, making ZERO answers-provider calls (ADR-014, per-egress clearance; the answers LLM is a distinct residency surface from the embedder, so the embedder's clearance does not clear it). That check is fail-closed — an absent or non-`True` declaration reads as egressing. **The narrowing grants no clearance**: `answers_privacy_cleared` stays default-false, the real path is unchanged, and owner clearance for the answers residency surface remains an open prerequisite.
- **Enforced by.** `api/theygrow_api/services/query_service.py` (`_ensure_answers_cleared` runs first, before `retrieve`/build/call) + `api/tests/test_query_service.py` (`test_answers_fail_closed_when_uncleared_zero_calls`, asserting `AnswersNotReady` and zero recorded provider calls), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P4 (statement and scope amended A2-P3: the gate restated as egress-scoped, with the in-perimeter exemption and its fail-closed default; the narrowing grants no clearance — `L2-DL-003`, `L2-P3-INV-001`).
- **Scope.** Covers the answers/chat egress only (the second §4 surface); the query-embedding egress stays gated by `embedder_privacy_cleared` inside `retrieve()` (`L2-P3-INV-001` / ADR-011). It is a structural refusal (loud no-op), not a content degradation. Since A2-P3 it also does not bind what an in-perimeter answers provider computes — only that one claiming the exemption declared it structurally; that a declaring provider genuinely opens no socket is a property of that provider's code, not something this gate can verify.

### M4-P4-INV-002 — Grounded answers are closed-corpus or honestly degraded

- **Statement.** A non-`None` `answer_text` is produced ONLY from retrieved + cited family episodic memory — never a parametric/model or web fallback. Three independent edges enforce this: the prompt carries only retrieved `chunk_text`; the parser rejects any `cited_chunk_id` absent from the assembled context (a fabricated citation → suppressed `parse_failure`); and a pre-provider grounding gate (`grounding_min_segments`) returns an honest `no_evidence` result with ZERO provider calls below the bar. A model-declared `no_evidence` (present-but-irrelevant context) also suppresses the answer.
- **Enforced by.** `api/theygrow_api/services/context_assembler.py` (`parse_structured_answer` citation grounding) + `api/theygrow_api/services/query_service.py` (the grounding gate + degradation contours) + `api/tests/test_query_service.py` (`test_fabricated_citation_is_parse_failure`, `test_no_context_degrades_with_zero_answers_calls`, `test_present_but_irrelevant_context_llm_declares_no_evidence`), run by `pytest api`.
- **Landed in.** M4-P4.
- **Scope.** Family episodic memory is the only grounded source at M4 (canon/KB is M5, out of perimeter), so provenance is family-observation lineage only. Grounded-but-uncertain answers are RETURNED with an honesty flag (ADR-015), not suppressed — they remain closed-corpus (cited retrieved context). These are deterministic seam-mechanics guarantees with injected fakes; real retrieval recall / grounding QUALITY is the M4-CLOSE eval, not enforced here.

### A1-P1-INV-001 — The spa-split refactor is gated by a three-level parity suite

- **Statement.** Every A1 `spa-split` packet must pass an automated three-level parity threshold against committed baselines of the pre-split app: **(a)** DOM-snapshot equality for `header`, `#mainTable` (head, body digest, and full-body hash), `footer.control-footer`, `#zpdEmptyState` and the four modals across four boot states at two viewports, plus a SHA-256 per skill-modal body for all 174 skills; **(b)** pixel-equal screenshots of those surfaces at 1280×800 and 412×760, captured on a platform fixed by a pinned browser container rather than by the CI runner image; **(c)** behavioural smoke over the main tick → ZPD-recompute → persist → reload loop, the no-profile honest-degradation refusal, the activity→skill deep link and modal stack, service-worker registration / offline boot from precache / the PWA update flow, and the kb-load error path. Baselines are never written implicitly: `updateSnapshots: 'none'` makes a missing or changed baseline fail, and only an explicit `--update-snapshots` run may rewrite one. *(Namespace note: id follows the `A1-P{k}` packet namespace of the spa-split milestone, mirroring the `VDK-P3-INV-001` precedent for a non-`M{N}` namespace; the "Entry format" footer below is intentionally left unedited, matching how the decision-log treats its non-spine namespaces.)*

### A1-P3-INV-001 — The image ships everything the shell references, and the shell and the precache agree

- **Statement.** Two directions are machine-asserted on every CI run against the **real** `app/Dockerfile` `COPY` list: **(a)** every same-origin asset referenced by a shipped HTML shell, and every entry of `OFFLINE_URLS` in `app/sw.js`, resolves to a path the image ships **and** that exists on disk; **(b)** every same-origin asset referenced by a shipped shell is **also** precached by name in `OFFLINE_URLS`. Direction (a) exists because `app/Dockerfile` has no wildcard `COPY` while the parity server serves from the `app/` directory on disk — a forgotten `COPY` therefore passes the whole suite and 404s only in production. Direction (b) exists because module-mount bumps are copy-forward (`A1-DL-004`): both the old and the new mount version stay shipped, so (a) alone would stay green while `index.html` pointed at one version and `OFFLINE_URLS` still listed the other. The `COPY` parser fails **closed** — any form it does not fully understand throws, since a skipped line is a loud false negative while a mis-parsed destination is a silent false positive.
- **Enforced by.** `app/tests/delivery-contract.spec.js` (the `ship list — app/Dockerfile ships everything the shell needs` describe-block), run in the `contract` project of `app/playwright.config.js` via `scripts/parity-suite.sh` — invoked as the `parity` job in `.github/workflows/ci.yml`. Sources are the real `app/Dockerfile`, `app/sw.js` (`OFFLINE_URLS` read textually, with a loud throw on no-match, because `app/sw.js` calls `self.addEventListener` and cannot be `require()`d), `app/manifest.json` (`icons[].src`), and the shipped HTML shells `app/index.html` and `app/offline.html`.
- **Landed in.** A1-P3.
- **Scope.** Covers assets referenced from HTML attributes (`href=`/`src=` values beginning with `/`), manifest icon sources, and the precache list — since A1-P6 that surface includes the `<link rel="modulepreload">` delivery hints, so every hinted module is asserted shipped-and-precached as a shell reference in its own right, independently of the import walk that also reaches it. It does **not** cover: assets referenced only from JavaScript string literals — `fetch('/kb-v1.json')` in the shell is covered incidentally, via `OFFLINE_URLS`, and a future runtime-fetched asset that is not precached would be invisible; `url()` / `@import` references inside CSS (there are none today); `app/.dockerignore`, which the guard does not consult, so a future ignore pattern matching `m/` would make `COPY m/` ship nothing with this guard still green; and production `Content-Type`, which comes from the base image's `mime.types` and is observed only by the promotion-smoke curl in `docs/RUNBOOK.md`. The copy-forward / never-overwrite half of the `A1-DL-004` mount contract is a documented owner procedure, **not** a gate — nothing here can detect bytes changing at an already-published URL within one commit.

### A1-P4-INV-001 — The shipped module import graph is shipped and precached, transitively

- **Statement.** Every module the shell's `<script type="module">` entries import, transitively, resolves to a path the image ships **and** that is precached by name in `OFFLINE_URLS`. - **Scope.** Covers what the ENGINE refuses, on a connection that has applied `app/m/v1/store/schema/001-core.sql`. It does not prevent a future migration from dropping the triggers (that is the migration mechanism's problem, designed with P4), and it says nothing about whether the application ever tries to update — the write path is P4. It does not cover the file: a caller with the passphrase and a raw SQLite connection can do anything, which is why the encryption key and the export contour are separate decisions.

### LSC-P2-INV-002 — A declarative marker never moves a computed number

- **Statement.** PDR-033 fixes slot 6 as **one** computing field (gestational age at birth, weeks + days, from which corrected-age policy is derived) and **three** declarative markers (bilingual environment, atypical development, unknown early history). The enforced property is structural and behavioural: flipping every marker through every value — set, cleared, changed — leaves the output of every computing view **byte-identical**. A marker changes what the product is allowed to assert; it never changes a number. The computing surface is reachable from attribute events through exactly one view (`v_child_profile`), which names the four non-marker attributes explicitly and therefore cannot reach a marker at all. All three markers carry the sensitivity flag by CHECK constraint rather than by the caller remembering.
- **Enforced by.** `app/tests/schema/test_store_markers.py` — the behavioural half (`test_markers_never_move_a_computed_number`, which snapshots the computing surface, flips all three markers through four values each, and re-compares after every write), an anti-vacuity test asserting the snapshot is non-empty and numerically correct, the textual half over the view SQL, and the CHECK-constraint half. Run by `pytest app/tests/schema` in the `quality` job.
- **Landed in.** L1-P2.
- **Scope.** Covers the SQL computing surface, enumerated in `COMPUTING_VIEWS`. A computation added in JavaScript that read `v_child_marker` directly would not be caught here — the guard is over the schema, which is the layer that freezes. `v_child_age` is deliberately clock-free (it yields a corrected baseline DATE, not an age), so the comparison is exact rather than time-sensitive; the subtraction happens at the call site.

### LSC-P2-INV-003 — The "do not collect" list is closed, and two column names are reserved

- **Statement.** Two denylists over the whole schema — every table, view, index and trigger name, and every column of every table and view. **(a)** PDR-033's closed list: no clinician-instrument score (GMFCS/MACS/CFCS, Vineland, PEDI-CAT, HINE, ASQ-like), no numeric probability of a diagnosis or risk, no syndrome curve, no severity or percentile, no multiple-birth or deprivation coefficient, and no `regression` attribute — regression is derived from the journal, not stored. The `child` row is asserted to carry `id` and `created_at_utc` and nothing else, and the child-attribute enum is asserted **closed** at exactly the eight values PDR-033 permits, so the list cannot be extended by adding a column somewhere else. **(b)** `sql_deleted` and `last_modified` are reserved: `@capacitor-community/sqlite` rewrites `DELETE FROM … WHERE …` into a soft-delete `UPDATE` when a table carries both, so a schema that grew those names would silently stop erasing quote-basis rows and slot 15's erasure would become a lie told by a third-party plugin.
- **Enforced by.** `app/tests/schema/test_store_denylist.py` — name scan, column scan, the closed-enum assertion parsed out of the live DDL, the two reserved names, and the shape assertions on `child` and `participant`. Run by `pytest app/tests/schema` in the `quality` job.
- **Landed in.** L1-P2.
- **Scope.** Matches **names**, not meaning: a forbidden quantity stored in a column called `value` would pass, which is why the child-attribute enum is asserted closed rather than relying on the name scan alone. It covers the schema, not the UI — nothing here stops a surface from asking a question the store then declines to hold. Half (b) is pinned to the wrapper this packet selected; `app/tests/store-supply-chain.spec.js` asserts the wrapper behaviour it depends on has not drifted.

### LSC-P2-INV-004 — The schema converges under both CRDT candidates, and neither library ships

- **Statement.** The frozen schema is checked against the merge semantics of **both** ADR-040 §3 candidates — Automerge and Loro — and the library itself stays **unselected** (that is L7). For each library: concurrent appends on two replicas lose nothing; merge order does not change the merged journal; the projection is identical on both replicas afterwards; diary text edited by overwrite converges to one value; quote erasure converges while the assertion survives; and an id minted at creation survives the merge as the key. The two libraries are then asserted to agree with **each other** on the merged journal and its projection, so choosing either later creates no lock-in and no migration. The containment half is enforced in the opposite direction: no shipped byte mentions either library, no shipped module imports a bare or package-path specifier, and neither is a runtime dependency of either `package.json`.
- **Enforced by.** `app/tests/merge-semantics.spec.js` (one adapter per library, the same assertions run against both, plus the cross-library agreement test and the device-local-column tests) and `app/tests/store-supply-chain.spec.js` (containment, the plugin-method allowlist, and the exact-pin assertions) — both in the `contract` project, run by `scripts/parity-suite.sh` as the `parity` job.
- **Landed in.** L1-P2.
- **Scope.** Checks the SCHEMA's merge behaviour, not a sync implementation: there is no relay, no key scope and no grant model, and none is in this milestone. The projection rule is ported into the spec rather than executed as SQL — a CRDT document is not a SQLite connection — so the rule is pinned in two places and `app/tests/schema/test_store_projections.py` holds the SQL side. It says nothing about performance, document size, or how either library behaves on a journal of realistic length.

### LSC-P2-INV-005 — No family datum exists without an author and a subject

- **Statement.** `journal_entry.author_participant_id` and `journal_entry.subject_child_id` are both `NOT NULL` and both foreign keys, enforced with `PRAGMA foreign_keys = ON`; the detail tables key on the spine, so a child attribute cannot name a different child than the entry that carries it. This is slot 1 made structural — a mark is an **attributed assertion**, never an impersonal fact — and it is also the defensible form of the "a default profile always exists" premise: the store **does not** auto-create a child (that was rejected as an owner decision in the A0 spa-polish entry — "it invents a family record the owner did not ask for, to paper over a write path that should simply report failure"), it makes an orphan impossible instead. The one row bootstrap does create is the `is_self` participant, which is an id to attribute to rather than a family record, and which carries no name column at all.
- **Enforced by.** `app/tests/schema/test_store_slots.py::test_an_assertion_cannot_be_anonymous` (both the unknown-author and the null-subject case), `test_store_denylist.py::test_the_participant_row_carries_no_name`, and the guard in `app/m/v1/store/journal.js::appendEntry` asserted by `app/tests/store-unit.spec.js`. Run by `pytest app/tests/schema` in the `quality` job and the `contract` project in the `parity` job.
- **Landed in.** L1-P2.
- **Scope.** Covers the schema's refusal, on a connection with foreign keys ON — the store turns them on at open, and a connection that did not would not be enforcing this. It does not make the WRITE path honest about failure; that behaviour (the A0 fix: revert the checkbox, open the create-profile modal, emit nothing) still lives in `app/m/v1/surfaces/skill-completion.js` and is P4's to re-express against the native store.

### LSC-P2-INV-006 — The bundled engine carries FTS5, and the shipped DDL applies to it

- **Statement.** On a real Android device, the SQLCipher engine the app links (`net.zetetic:sqlcipher-android`, bundled — **not** the Android system SQLite, which guarantees neither) compiles `ENABLE_FTS5` in, reports a SQLite version at or above the `3.37.0` floor STRICT tables need, opens in WAL, and reports a non-empty `PRAGMA cipher_version` so the database is demonstrably encrypted rather than assumed to be. The DDL read out of `assets/public/` — the same artifact the WebView fetches — applies clean, passes `integrity_check`, and its append-only triggers fire. Russian tokenization is asserted **as measured**, including what it does not do: `unicode61` folds Cyrillic case but does **not** fold `ё` to `е`, which is recorded as the L2 word-form gap rather than assumed away. The absence of `ENABLE_ICU` is asserted too, as a recorded fact about the engine — see `LSC-DL-002` on why the substance secured instead is a fully rebuildable index.
- **Enforced by.** `native/android/app/src/androidTest/java/app/theygrow/StoreEngineTest.java` and `BridgeSmokeTest.java` — run by the `android-instrumented` job in `.github/workflows/ci.yml`.
- **Landed in.** L1-P2.
- **Scope.** **This is not a per-push gate.** The job runs on `pull_request` and `workflow_dispatch` only, by owner decision on CI spend, so a regression introduced by a later packet is caught at PR time rather than at push time — possibly several commits after its cause. It covers one emulator image (API 34, `google_apis`, x86_64) and says nothing about other API levels, other ABIs, or physical devices; the on-device smoke in `docs/RUNBOOK.md` is what covers a real handset. `BridgeSmokeTest` covers the bridge call path and that the app opens its store at boot; it does not exercise the write path, which does not exist until P4.

### LSC-P3-INV-001 — The export artifact is readable using only what it declares about itself

- **Statement.** The archive carries a verbatim copy of `app/m/v1/export/declaration.json` inside its own `index.json`, and that copy is sufficient to interpret every file in the archive: which datasets exist, which columns each carries, what every column means in plain Russian, in what order the journal is written, and how a spine row is joined to its detail row. The enforced property is proven by a reader that **imports nothing but the Python standard library** — asserted structurally, by parsing the reader's own import statements, so an import added later cannot quietly turn the proof into a statement about this repository. Every declared dataset's column list is checked against what its declared query actually returns on the real frozen schema, so the artifact cannot promise a field it does not deliver or deliver one no reader was told about; every declared file must be present and non-empty, and the zero case (`text/diary.txt` until L2) is worded as a fact about the source rather than left as an empty file that reads as data loss. This closes PDR-026 §4's fifth accompanying rule, which L1-P2 deferred to this packet. *(Namespace note: continues the `LSC-` namespace declared in `docs/execution-map.md`; packets keep `L1-P{k}`. The "Entry format" footer below is intentionally left unedited.)*
- **Enforced by.** `app/tests/export/test_artifact_selfdescribing.py` (with the reader in `app/tests/export/blind_reader.py`) and `app/tests/export/test_artifact_shape.py`, run by `pytest app/tests/export` in the `quality` job of `.github/workflows/ci.yml`. The artifact under test is built by the **shipped** builder: `app/tests/export/harness.py` runs the declared queries against a real SQLite database carrying the real `001-core.sql`, then shells out to `node` on `app/m/v1/export/build.js` — the same discipline `app/tests/schema/harness.py` uses when it applies the DDL through a port of the wrapper's own splitter. `app/tests/schema/test_store_slots.py::test_each_accompanying_rule_is_closed_or_addressed` resolves rule 5 to the blind-reader test, so the rule is closed by a live test rather than by a deferral string.
- **Landed in.** L1-P3.
- **Scope.** Covers the artifact's **structure and its self-description**, on a journal the test seeds. It does **not** prove the artifact is useful: until L1-P4 lands the write path, nothing writes family data to the journal, so on a real device the archive is correct and nearly empty. It does not cover the PDF print layer, which is the second checkpoint of this packet and carries its own invariant. It says nothing about re-importing the artifact — import is L6, and the README says so rather than implying a round trip.

### LSC-P3-INV-002 — The artifact is produced locally, on an explicit human action, and never transmitted

- **Statement.** No module under `app/m/v1/export/` contains a request primitive at all (`XMLHttpRequest`, `sendBeacon`, `WebSocket`, `EventSource`, or any `navigator.` reach), and every `fetch` call site addresses its target through a knob on the `EXPORT_CONFIG` surface rather than a literal URL — so a new off-device read has to be declared in the config surface before it can compile past the gate. The only fetch the contour makes is of its own declaration, which on the native channel is a local asset read served by Capacitor with no network involved. Nothing schedules an export: no `setInterval`, no `setTimeout`, no `requestIdleCallback` and no listener registration anywhere in the contour, and the surface that wires the button is asserted to listen for `click` and nothing else — so an unencrypted archive cannot appear on the filesystem without a person asking for it in that moment. The sink is **one method wide** and the count is asserted: `ALLOWED_SINK_METHODS` is exactly `['createDocument']`, and the Android plugin behind it uses `ACTION_CREATE_DOCUMENT`, which needs **no storage permission** — the app can write the single document the parent picked in the system file picker and nothing else, cannot list a directory, cannot read a file and cannot choose a path of its own. No export module touches WebView storage. The interface states two sentences verbatim, before the action rather than after it — that media is not in the archive, and that there is no cloud backup of this data — and both are asserted as exact strings so they cannot drift into a hedge one word at a time.
- **Enforced by.** `app/tests/export-contour.spec.js`, run in the `contract` project of `app/playwright.config.js` via `scripts/parity-suite.sh` — the `parity` job in `.github/workflows/ci.yml`. The device half is `native/android/app/src/androidTest/java/app/theygrow/ExportSinkTest.java` (the byte path, truncation, and that the first-party plugin is registered and answers through the injected bridge), run by the `android-instrumented` job.
- **Landed in.** L1-P3.
- **Scope.** Covers **shipped source text and the declared sink boundary**, plus the byte path on one emulator image. Like `LSC-P1-INV-001` it is a drift gate over honest code, not an adversary: an obfuscated dynamic lookup would not be caught. It does not prove Android honours the picker's URI grant, nor that the parent chose a sensible location — the archive is plaintext family data and where it lands is the parent's choice by design, which the interface states rather than manages. **The device half is not a per-push gate**: `android-instrumented` runs on `pull_request` and `workflow_dispatch` only, by the standing owner decision on CI spend, so a sink regression is caught at PR time rather than at push time. The system file picker's own UI is deliberately not automated — see `ExportSinkTest`'s header and the owner-run smoke in `docs/RUNBOOK.md`.

### LSC-P3-INV-003 — The archive carries the requesting participant's records, and no other participant's private ones

- **Statement.** Every dataset whose query reads a visibility column (`visibility_class`, `owner_participant_id`, `private_to_participant_id`) binds the requesting participant's id as a declared parameter, and the declaration states the rule in its own published words: the archive carries every child-shared entry plus the private entries of the participant who asked for it, and each participant exports their own. The parameter is bound by name, and an unknown name raises rather than binding `NULL` — a scope filter that silently bound `NULL` would widen the archive past its requester while every other assertion stayed green. Absence is asserted as well as presence, and asserted **in the bytes** rather than only in the parsed datasets, so a leak into a rendered text file cannot pass.
- **Enforced by.** `app/tests/export/test_artifact_selfdescribing.py::test_the_archive_holds_the_requesters_own_private_records` and `::test_the_archive_holds_no_other_participants_private_records`, over a fixture (`app/tests/export/harness.py::seed_family`) that deliberately holds a second participant with private records, a shared record, and one quote per participant — because a scope filter shown only shared data passes while doing nothing. The structural half is `app/tests/export-contour.spec.js`, which fails if a dataset reads a visibility column without binding the requester. Run by `pytest app/tests/export` and the `parity` job.
- **Landed in.** L1-P3.
- **Scope.** On this rung there is exactly one participant, so the exclusion half changes no observed behaviour today. It is enforced now because the **format is published**: a declaration that had promised "all private areas" would already have committed the product to putting a co-parent's private records into someone else's archive when a second participant arrives at L7. It covers what the declared queries select; it does not cover a future dataset added without a visibility column, which is why the structural gate keys on the column names rather than on a list of dataset names.

### LSC-P3-INV-004 — Two exports of the same journal are the same archive, and the export time lives in one file

- **Statement.** Given the same journal state and the same `exported_at_utc`, the artifact is **byte-identical**; given the same journal state and a different export time, every file is byte-identical except `MANIFEST.json`. This is achieved structurally rather than by convention: entries are STORED (zip method 0, never compressed — DEFLATE output is not byte-stable across implementations, so two devices holding the same journal would otherwise disagree), entry timestamps are pinned to the DOS epoch instead of the wall clock, entry order is the declared file order, and the journal is ordered by `(entry_at_utc, id)` — the replica-identical total order — with the device-local `seq` deliberately absent from the artifact entirely. The anti-vacuity direction is asserted too: a changed journal must change the archive, and no file outside `MANIFEST.json` may contain the export timestamp.
- **Enforced by.** `app/tests/export/test_artifact_deterministic.py` (all four directions) and `app/tests/export/test_artifact_shape.py::test_every_entry_is_stored_uncompressed_and_time_pinned`, run by `pytest app/tests/export` in the `quality` job; the declared half (`compression: stored`) is cross-checked against the config knob by `app/tests/export-contour.spec.js`.
- **Landed in.** L1-P3.
- **Scope.** Covers the archive the builder produces from a given read-out. It does not cover the read-out itself being stable under concurrent writes — there is no write path until P4 — and it makes no claim about the archive being identical across **format versions**: a `format_version` bump is exactly the event that is allowed to change these bytes. The print layer's contribution to this property is the second checkpoint's to establish.

### LSC-P3-INV-005 — The print layer is PDF/A-2b, and the claim is verified rather than asserted

- **Statement.** The archive's `print/archive.pdf` is written to PDF/A-2b and says so in two places a reader can check — the XMP packet (`pdfaid:part` 2, `pdfaid:conformance` B, in an unfiltered metadata stream) and the artifact's own `declaration.json`. The enforced property is that **the claim and the file agree**, checked from two directions at two costs. Structurally, on every push: no `/Encrypt`; every `FontDescriptor` embeds a `FontFile2` with a declared `/Length1`; an `OutputIntent` with `/S /GTS_PDFA1` and an embedded `/N 3` destination profile; XMP dates equal to the document information dictionary's; a trailer carrying `/ID`, `/Root` and `/Info`; and a cross-reference table every one of whose offsets is followed to the object it claims to start. Certifyingly, at PR or on dispatch: veraPDF `--flavour 2b` against a fixture built by the shipped builder, failing the job unless the report says `compliant="true"`. Text extraction is asserted by **round trip** rather than by presence — the CMap is walked and the first page read back, requiring Cyrillic to survive and no replacement character to appear — because an Identity-H file with a broken `ToUnicode` renders perfectly and yields nonsense when copied. The declared degradation is asserted with it: a codepoint outside the embedded font renders as U+FFFD **in the PDF only**, the text files and `index.json` always carry the exact characters, and the declaration names which copy is authoritative.
- **Enforced by.** `app/tests/export/test_pdf_structure.py`, run by `pytest app/tests/export` in the `quality` job of `.github/workflows/ci.yml`; and the `Validate the print layer against PDF/A-2b` step of the `android-instrumented` job, over a fixture produced by `app/tests/export/emit_fixture.py` through the same `harness.py` the pytest suite uses. The two vendored binaries the layer requires are pinned by SHA-256 in `app/tests/export-contour.spec.js` (`parity` job).
- **Landed in.** L1-P3.
- **Scope.** **The certifying half is not a per-push gate.** `android-instrumented` runs on `pull_request` and `workflow_dispatch` only, by the standing owner decision on CI spend, so a conformance regression is caught at PR time rather than at push time — the same trade already accepted for the device layer, and the reason the cheap structural half exists at all. veraPDF is installed from upstream's unversioned "latest" URL, since no version-pinned URL is published, so the tool version is echoed into the log rather than asserted. The gate covers the artifact this repository's fixture produces; it says nothing about a PDF built from a family's real journal, which no CI job will ever see. It does not assert that any particular viewer renders the file, nor that the embedded font covers any particular language beyond the round trip's Cyrillic — coverage gaps are handled by the declared U+FFFD degradation rather than prevented.

## Entry format (for future entries)

- **Id.** `M{N}-P{k}-INV-{NNN}` — `N` is the milestone number, `k` is the packet number within the milestone, `NNN` is zero-padded sequence within the packet (`001`, `002`, …).
- **Required fields.**
  - **Statement.** The invariant in one sentence.
  - **Enforced by.** File path(s) of the enforcing artifact — test, lint rule, schema constraint, runtime guard, or CI workflow.
  - **Landed in.** Packet id + commit SHA where enforcement was introduced.
  - **Scope.** What the invariant covers, and explicitly what it does not.
