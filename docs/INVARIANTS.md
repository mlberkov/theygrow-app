# Enforced invariants — theygrow-app

## Bar

`INVARIANTS.md` is **enforced-only**. An invariant goes here only when a packet enforces it in code — a test, a lint rule, a schema constraint, a runtime guard, or a CI gate. Intent and runtime contract do **not** live here:

- **Intent-level invariants** (what the contract says we will do) live in `AGENTS.md` §2 and §3.
- **Documented runtime behavioral contract** (what the running system must do, before code lands) lives in [`RUNTIME-INVARIANTS.md`](RUNTIME-INVARIANTS.md).

Keeping this file enforced-only prevents it from drifting into a wish list.

## Invariants

### M1-P3-INV-001 — No secrets committed

- **Statement.** No secret or credential material is committed to the repository.
- **Enforced by.** `.pre-commit-config.yaml` (gitleaks hook) and `.github/workflows/ci.yml` (runs the gitleaks hook via `pre-commit run --all-files`, with full history fetched).
- **Landed in.** M1-P3.
- **Scope.** Covers tracked content and commit history reachable in CI. Public, non-secret identifiers (e.g. the GA4 Measurement ID, the GCP project id / region) are not secrets; should the scanner ever flag one, the remedy is an exact non-secret allowlist entry in a `.gitleaks.toml` at the repository root. No such file exists today and nothing has been allowlisted — the hook runs on its stock ruleset. Genuine secrets are never allowlisted.

### M1-P3-INV-002 — Contract integrity

- **Statement.** Within the contract + spine documents, three conditions hold: (a) superseded stack names do not reappear as active targets; (b) the legacy pre-rename repository directory name does not appear; (c) live-infra identifiers stay confined to `docs/RUNBOOK.md`.
- **Enforced by.** `scripts/check-contract-integrity.sh`, wired into `.pre-commit-config.yaml` (local hook) and `.github/workflows/ci.yml`. The script holds the authoritative match patterns for all three checks; they are intentionally not restated inline here, since this file is itself within the scanned corpus.
- **Landed in.** M1-P3.
- **Scope.** Governs the contract + spine corpus: `AGENTS.md`, `CLAUDE.md`, `docs/INVARIANTS.md`, `docs/RUNTIME-INVARIANTS.md`, `docs/execution-map.md`, `docs/RUNBOOK.md`, `docs/product/BuildPlan.md`, `docs/product/TechSpec.md`, `.cursor/rules/masterplan.mdc`. Live-deploy paths are out of scope — they carry live-infra identifiers as operational reality. Historical artifacts (`docs/decision-log.md`, `data/mvp_masterplan.md`) are exempt — they record the superseded plan by design. This promotes the previously-manual P1/P2 negative-checks into an enforced gate. P4 tightened check (b) to a strict ban by removing its interim pairing exception once the residual naming sweep was complete.

### M2-P2-INV-001 — No child PII in logs / telemetry (forward guard)

- **Statement.** No known child-PII field (child name, diary text, birthdate / dob) is emitted through the logging boundary: known PII field names carried on a log record are redacted to `[REDACTED]` before any handler formats the record.
- **Enforced by.** `api/theygrow_api/logging.py` (`PiiRedactionFilter`) + `api/tests/test_logging_redaction.py`, run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M2-P2.
- **Scope.** A **forward guard**: it establishes telemetry/redaction discipline from the first byte of backend code (AGENTS.md §4). At P2 there is **no live child-PII data path** — those arrive at M3 — so this covers the logging-boundary redaction *mechanism* and its test, not end-to-end coverage over live child data; coverage extends as data paths land (M3 → M5). It governs known structured PII field names only, not free-text message bodies.

### M4-P1-INV-001 — Sparse FTS leg is index-backed

- **Statement.** The sparse (lexical) retrieval leg matches against a generated, DB-maintained `tsvector` (`event_chunks.chunk_text_tsv`, `to_tsvector('simple', chunk_text)`) backed by a GIN index, and is community-scoped — a query never crosses community boundaries.

- **Landed in.** M4-P1.
- **Scope.** Covers the sparse leg's **mechanics** only. It does **not** establish Russian lexical recall adequacy: the `'simple'` config does no morphological stemming (the documented limitation and named port-out trigger, `M4-DL-001`); recall is measured at the M4-close mini-eval, not here. The dense leg, RRF fusion, and the episodic-eligibility filter are out of scope (M4-P2/P3).

### M4-P2-INV-002 — Embeddings backfill is fail-closed without the ZDR clearance gate

- **Statement.** The offline embeddings backfill sends no `chunk_text` **out of the perimeter** and writes nothing unless the operator-set `embedder_privacy_cleared` flag (the ZDR + DPA + EU-residency clearance) is set — and, on the real path, the embedder endpoint/key are present. With the gate unmet the run refuses before any provider call or DB write (zero provider calls, zero writes). The gate is scoped to **egress**: it applies to the real provider path and to any injected provider that does not structurally declare zero egress, and is skipped only for an in-perimeter provider (`performs_no_egress is True`), which removes the third-party surface rather than satisfying its clearance. That check is itself fail-closed — an absent or non-`True` declaration reads as egressing — so the narrowing cannot become a bypass by omission.
- **Enforced by.** `api/theygrow_api/embeddings_backfill.py` (`_ensure_embedder_cleared` / `_build_provider`, raising `EmbedderNotReady` before any text egress) + `api/theygrow_api/ports/provider.py` (`performs_no_egress`, the fail-closed declaration predicate — private to the backfill until A2-P3 hoisted it beside the two ports it now serves) + `api/theygrow_api/config.py` (the default-false `embedder_privacy_cleared` flag) + `api/tests/test_embeddings_backfill.py` (`test_fail_closed_when_uncleared`, `test_fail_closed_when_unconfigured`) + `api/tests/test_seed_staging.py` (`test_unmarked_provider_still_gated_when_uncleared`, `test_truthy_declaration_is_not_enough`), run by `mypy api` + `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P2 (statement amended A2-P2: the gate restated as egress-scoped, with the in-perimeter exemption and its fail-closed default — `L2-DL-002`; amended A2-P3: the declaration predicate moved to `ports/provider.py`, and the same egress scoping was extended to the READ path — `L2-DL-003`, `L2-P3-INV-001`).
- **Scope.** A structural §4 gate over the one permitted child-text egress (ADR-011 §1). It governs the offline backfill path; the read path's query-embedding gate is the same mechanism and is stated at `L2-P3-INV-001` (there is still no live *request* path that embeds — chat is M5). It binds the gate mechanism, not the external provider's actual ZDR posture (an operational precondition the owner clears). Since A2-P2 it also does not bind what an in-perimeter provider computes — only that one which claims the exemption has declared it structurally; that a declaring provider genuinely performs no I/O is a property of that provider's code, not something this gate can verify.

### M4-P2-INV-003 — Embeddings backfill is idempotent and index-after-population

- **Statement.** The backfill embeds only `pending` (and, unless `--no-retry-failed`, `failed`) chunks and skips `ready` ones, so a re-run over a fully-embedded corpus is a no-op (no duplicate writes, no extra provider calls); a provider error marks the batch `failed` for retry, never a partial vector. The HNSW index is built by the backfill AFTER bulk population, not by the migration.
- **Enforced by.** `api/theygrow_api/embeddings_backfill.py` (status-driven selection; `CREATE INDEX IF NOT EXISTS` after population) + `api/tests/test_embeddings_backfill.py` (`test_backfill_is_idempotent`, `test_backfill_marks_failed_then_retries`, `test_backfill_builds_hnsw_index_after_population`) + `api/tests/test_embedding_schema.py` (`test_migration_alone_builds_no_hnsw_index`), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P2.
- **Scope.** Covers the offline backfill pass over already-derived chunks. Embedding quality / vector correctness beyond dimension is out of scope; the injected fake provider exercises mechanics, not a live embedder.

### M4-P4-INV-001 — Answer synthesis is fail-closed without the answers ZDR clearance gate

- **Statement.** The grounded-ask service sends family context to the answers LLM and synthesizes an answer ONLY when `answers_privacy_cleared` is set; uncleared (or endpoint/key missing) it raises `AnswersNotReady` before any provider call or text egress, making ZERO answers-provider calls (ADR-014, per-egress clearance; the answers LLM is a distinct residency surface from the embedder, so the embedder's clearance does not clear it). That check is fail-closed — an absent or non-`True` declaration reads as egressing. **The narrowing grants no clearance**: `answers_privacy_cleared` stays default-false, the real path is unchanged, and owner clearance for the answers residency surface remains an open prerequisite.
- **Enforced by.** `api/theygrow_api/services/query_service.py` (`_ensure_answers_cleared` runs first, before `retrieve`/build/call) + `api/tests/test_query_service.py` (`test_answers_fail_closed_when_uncleared_zero_calls`, asserting `AnswersNotReady` and zero recorded provider calls), run by `pytest api` in `.github/workflows/ci.yml`.
- **Landed in.** M4-P4 (statement and scope amended A2-P3: the gate restated as egress-scoped, with the in-perimeter exemption and its fail-closed default; the narrowing grants no clearance — `L2-DL-003`, `L2-P3-INV-001`).
- **Scope.** Covers the answers/chat egress only (the second §4 surface); the query-embedding egress stays gated by `embedder_privacy_cleared` inside `retrieve()` (`L2-P3-INV-001` / ADR-011). It is a structural refusal (loud no-op), not a content degradation. Since A2-P3 it also does not bind what an in-perimeter answers provider computes — only that one claiming the exemption declared it structurally; that a declaring provider genuinely opens no socket is a property of that provider's code, not something this gate can verify.

### M4-P4-INV-002 — Grounded answers are closed-corpus or honestly degraded

- **Statement.** A non-`None` `answer_text` is produced ONLY from retrieved + cited family episodic memory — never a parametric/model or web fallback. Three independent edges enforce this: the prompt carries only retrieved `chunk_text`; the parser rejects any `cited_chunk_id` absent from the assembled context (a fabricated citation → suppressed `parse_failure`); and a pre-provider grounding gate (`grounding_min_segments`) returns an honest `no_evidence` result with ZERO provider calls below the bar. A model-declared `no_evidence` (present-but-irrelevant context) also suppresses the answer.
- **Enforced by.** `api/theygrow_api/services/context_assembler.py` (`parse_structured_answer` citation grounding) + `api/theygrow_api/services/query_service.py` (the grounding gate + degradation contours) + `api/tests/test_query_service.py` (`test_fabricated_citation_is_parse_failure`, `test_no_context_degrades_with_zero_answers_calls`, `test_present_but_irrelevant_context_llm_declares_no_evidence`), run by `pytest api`.
- **Landed in.** M4-P4.
- **Scope.** Family episodic memory is the only grounded source at M4 (canon/KB is M5, out of perimeter), so provenance is family-observation lineage only. Grounded-but-uncertain answers are RETURNED with an honesty flag (ADR-015), not suppressed — they remain closed-corpus (cited retrieved context). These are deterministic seam-mechanics guarantees with injected fakes; real retrieval recall / grounding QUALITY is the M4-CLOSE eval, not enforced here.

### A1-P1-INV-001 — The spa-split refactor is gated by a three-level parity suite

- **Statement.** Every A1 `spa-split` packet must pass an automated three-level parity threshold against committed baselines of the pre-split app: **(a)** DOM-snapshot equality for `header`, `#mainTable` (head, body digest, and full-body hash), `footer.control-footer`, `#zpdEmptyState` and the four modals across four boot states at two viewports, plus a SHA-256 per skill-modal body for all 174 skills; **(b)** pixel-equal screenshots of those surfaces at 1280×800 and 412×760, captured on a platform fixed by a pinned browser container rather than by the CI runner image; **(c)** behavioural smoke over the main tick → ZPD-recompute → persist → reload loop, the no-profile honest-degradation refusal, the activity→skill deep link and modal stack, service-worker registration / offline boot from precache / the PWA update flow, and the kb-load error path. Baselines are never written implicitly: `updateSnapshots: 'none'` makes a missing or changed baseline fail, and only an explicit `--update-snapshots` run may rewrite one. *(Namespace note: id follows the `A1-P{k}` packet namespace of the spa-split milestone, mirroring the `VDK-P3-INV-001` precedent for a non-`M{N}` namespace; the "Entry format" footer below is intentionally left unedited, matching how the decision-log treats its non-spine namespaces.)*

### A1-P3-INV-001 — The image ships everything the shell references, and the shell and the precache agree

- **Statement.** Two directions are machine-asserted on every CI run against the **real** `app/Dockerfile` `COPY` list: **(a)** every same-origin asset referenced by a shipped HTML shell, and every entry of `OFFLINE_URLS` in `app/sw.js`, resolves to a path the image ships **and** that exists on disk; **(b)** every same-origin asset referenced by a shipped shell is **also** precached by name in `OFFLINE_URLS`. Direction (a) exists because `app/Dockerfile` has no wildcard `COPY` while the parity server serves from the `app/` directory on disk — a forgotten `COPY` therefore passes the whole suite and 404s only in production. Direction (b) exists because module-mount bumps are copy-forward (`A1-DL-004`): both the old and the new mount version stay shipped, so (a) alone would stay green while `index.html` pointed at one version and `OFFLINE_URLS` still listed the other. The `COPY` parser fails **closed** — any form it does not fully understand throws, since a skipped line is a loud false negative while a mis-parsed destination is a silent false positive.
- **Enforced by.** `app/tests/delivery-contract.spec.js` (the `ship list — app/Dockerfile ships everything the shell needs` describe-block), run in the `contract` project of `app/playwright.config.js` via `scripts/parity-suite.sh` — invoked as the `parity` job in `.github/workflows/ci.yml`. Sources are the real `app/Dockerfile`, `app/sw.js` (`OFFLINE_URLS` read textually, with a loud throw on no-match, because `app/sw.js` calls `self.addEventListener` and cannot be `require()`d), `app/manifest.json` (`icons[].src`), and the shipped HTML shells `app/index.html` and `app/offline.html`.
- **Landed in.** A1-P3.
- **Scope.** Covers assets referenced from HTML attributes (`href=`/`src=` values beginning with `/`), manifest icon sources, and the precache list — since A1-P6 that surface includes the `<link rel="modulepreload">` delivery hints, so every hinted module is asserted shipped-and-precached as a shell reference in its own right, independently of the import walk that also reaches it. It does **not** cover: assets referenced only from JavaScript string literals — `fetch('/kb-v1.json')` in the shell is covered incidentally, via `OFFLINE_URLS`, and a future runtime-fetched asset that is not precached would be invisible; `url()` / `@import` references inside CSS (there are none today); `app/.dockerignore`, which the guard does not consult, so a future ignore pattern matching `m/` would make `COPY m/` ship nothing with this guard still green; and production `Content-Type`, which comes from the base image's `mime.types` and is observed only by the promotion-smoke curl in `docs/RUNBOOK.md`. The copy-forward / never-overwrite half of the `A1-DL-004` mount contract is a documented owner procedure, **not** a gate — nothing here can detect bytes changing at an already-published URL within one commit.

### A1-P4-INV-001 — The shipped module import graph is shipped and precached, transitively

- **Statement.** Every module the shell's `<script type="module">` entries import, transitively, resolves to a path the image ships **and** that is precached by name in `OFFLINE_URLS`. ### LSC-P2-INV-001 — The journal is append-only, and its two exceptions are named

- **Statement.** Every table of the mark journal — the `journal_entry` spine and its three detail tables (`assertion`, `confirmation`, `child_attribute`) — refuses `UPDATE` and `DELETE` at the engine, through `BEFORE` triggers that `RAISE(ABORT)`. A correction is a new entry on top; a superseded assertion stays in the journal forever, which is what makes state at any past date reconstructible (PDR-026 §4 slot 10). ### LSC-P2-INV-002 — A declarative marker never moves a computed number

### LSC-P3-INV-004 — Two exports of the same journal are the same archive, and the export time lives in one file

### LSC-P4-INV-001 — A mark is an attributed assertion, and it travels with its author's confirmation

- **Statement.** Ticking a skill does not record the fact "mastered"; it appends an **attributed assertion** — an author, a subject child, an event date, an entry time and a stable id — and, in the **same transaction**, a `confirmation` of that assertion by the same author. The pairing is unconditional and nothing anywhere branches on how many participants exist, which is what makes "confirmed by one" the answer the general consensus function returns rather than a degenerate case somebody remembered to special-case (PDR-021). Un-ticking is a `skill_revoked` assertion appended on top, never a delete and never an update: the write path issues no `UPDATE` and no `DELETE` against any journal table. A skill's state is **projected** from the assertions on every read and is never stored as a fact — the in-memory set the render path consumes is a cache of that projection, rebuilt after every write, and authoritative for nothing. The projection carries the consensus columns (`confirmed_by`, `disputed_by`, `needs_refresh_by`) and the `origin` of the winning assertion, so the half-confirmed state is **expressed** at this rung even though no surface reads it until L7. With no subject, or with no author, or with a native store that did not open, the mark is **refused**: the checkbox is put back, the parent is told which of the three happened, and nothing is written (ADR-015).
- **Enforced by.** `app/tests/schema/test_write_path_projection.py`, run by `pytest app/tests/schema` in the `quality` job of `.github/workflows/ci.yml` — against a real SQLite database carrying the real frozen `001-core.sql`, with the projection query **read out of `app/m/v1/store/journal.js`** rather than retyped, so the query that is verified is the query that ships. The act's shape (one transaction, four statements, no `UPDATE`, no `DELETE`, both refusal paths) is `app/tests/write-path.spec.js` in the `contract` project via `scripts/parity-suite.sh` (`parity` job). The unconditionality of the confirmation is asserted against the shipped source, because the absence of a branch cannot be shown by reaching a branch.
- **Landed in.** L1-P4.
- **Scope.** Covers what the app **asks the store to do**, and what the SQL **means** on the real schema — deliberately in two places, by two mechanisms. `app/tests/write-path.spec.js` drives a recorder, not a database: it proves the statements, values and transaction grouping, and proves nothing about SQLite or the plugin. That the plugin and SQLCipher actually execute them is `android-instrumented`'s, and that job is **not a per-push gate** — it runs on `pull_request` and `workflow_dispatch` only. Both parity channels run without an injected Capacitor bridge, so **the parity suite exercises the localStorage backend, not the journal one**; what it proves here is that the web path is unregressed. It does not cover the surface behaviour of a half-confirmed node, which is L7's, nor prerequisite propagation, which stays a projection-time function and is never materialised.

### LSC-P4-INV-002 — The legacy import is re-runnable, and it never writes to the source

- **Statement.** Four properties, each a condition on the import being allowed to run at all. **(1)** Running it twice is running it once: every id is DERIVED — a SHA-256 over a declared namespace and the tuple it identifies, shaped as a UUID — so a second run computes the same ids, reads back which the store already holds, and appends only the remainder. There is no ledger and no "already imported" flag: the journal is the only record of what has been imported, so there is no second truth to drift. **(2)** An interrupted run leaves a state the next run **completes**: a child row and its attributes go in one transaction, marks go in batches, and an assertion is never split from its confirmation — so an interruption leaves a complete child and a prefix of their marks, and the resumption appends exactly the remainder with nothing written twice. **(3)** The import **cannot** write to `localStorage` — no module in the import path imports a writer from `app/m/v1/core/storage.js`, which is a stronger guarantee than not calling one, because a module that never imports a writer cannot become a second door by a later edit to its body. **(4)** Re-running does not undo what happened natively: a mark revoked on the device keeps its imported assertion under the same derived id, so the import appends nothing and the later revocation still wins the projection. Every imported entry carries `origin = 'migrated_legacy'`, the import date in the NOT NULL `event_date_local`, and a NULL event instant — the schema's own way of saying only the date is known — plus one confirmation by its author, which is "the author's assertion, confirmed by one" written into the data rather than inferred by a projection.
- **Enforced by.** `app/tests/import-legacy.spec.js` in the `contract` project via `scripts/parity-suite.sh` (`parity` job), including an interruption test that fails the *N*th transaction and then asserts that the interrupted run plus its resumption equals an uninterrupted run, with no id written twice. The SQL-level half — that a migrated mark and an authored one project identically but for `origin` — is `app/tests/schema/test_write_path_projection.py` (`quality` job).
- **Landed in.** L1-P4.
- **Scope.** Covers the import's control flow and the shape of what it writes, against a recorder. ### LSC-P4-INV-003 — No signal payload can carry family text

- **Statement.** The client signal surface accepts, as a payload value, only a **number**, a **boolean**, `null`, or a member of the **closed code list declared for that field**. There is no code path that accepts a free string, so a payload cannot carry a child's name, a skill title, or anything a parent wrote — not "does not", *cannot*. An undeclared kind, an undeclared field, a nested object, an array, a function and `undefined` are each refused; a refusal is counted rather than swallowed, and `emitSignal` never throws outward, because a telemetry bug must not take the write path down with it. Structurally, every `emitSignal` call site in the shipped surface names a declared kind with literal keys, no payload value is derived from an identifier that holds family text, and **no payload computes a value inline** — a call inside a payload is refused outright, which is what makes the family-text scan sound rather than merely present. **The surface's only sink is the device console.** It reaches no network primitive, and no emitter hands a signal to the analytics shim.
- **Enforced by.** `app/tests/signal-payload.spec.js` in the `contract` project via `scripts/parity-suite.sh` (`parity` job), over every shipped JavaScript module expanded from `app/Dockerfile`'s COPY list. The taxonomy, its codes and the guard live in `app/m/v1/core/signals.js`.
- **Landed in.** L1-P4.
- **Scope.** Covers **this** surface. It says nothing about the GA4 shim inlined in `app/index.html`, which predates it, is not behind this seam, and whose payloads are governed by §4 and `GA-DL-001` — on the native channel that shim is now inert (`LSC-P4-INV-004`), and on the web channel it is untouched and its disposition remains an open owner item. Like every source-text guard in this repository it is a drift gate over honest code, not an adversary: an obfuscated dynamic emit would not be caught. **Giving this surface a network sink is a separate owner decision on the escalation list (PDR-027 §2 — egress)**, and the absence of one is asserted rather than assumed, so it cannot be added as an implementation detail of adding a signal. The guard's soundness was established by mutation rather than by inspection — an earlier form of it failed **open** on exactly the shape a violation takes, and was replaced.

### LSC-P4-INV-004 — The native channel holds no second copy of the shell, and sends nothing to analytics

- **Scope.** **This closes the question `LSC-DL-001` (i) opened and `LSC-DL-002` carried**, and it closes the standing analytics item `LSC-DL-001` (o) **for the native channel only** — whether the *web* channel should carry analytics at all remains an open owner decision under the escalation list, with its own address at the milestone close. Covers one emulator image (API 34, `google_apis`, x86_64) and **is not a per-push gate**: `android-instrumented` runs on `pull_request` and `workflow_dispatch` only, by the standing owner decision on CI spend. The parity suite cannot substitute: both of its channels serve `native/www` over plain HTTP with **no Capacitor injected**, so both take the web branch, and the two analytics assertions in `behavior.spec.js` are statements about the web branch and remain so. The consequence, accepted deliberately, is that prose describing the historical defect must say "the previous generation" in words rather than encode a version number — which is the better sentence anyway, since a written-down number goes stale at the next bump exactly like the references this invariant exists to catch. **It does not carry the store claim.** That the app opens its encrypted store at boot on the native channel is executed only by `BridgeSmokeTest` on an emulator in `android-instrumented`; this guard would stay green against a shipped mount that was thoroughly broken, and is worth having only because it runs on every push, which is the window `LSC-DL-005` debt 13 leaves open.

### PPR-P1-INV-001 — The policy address serves the policy document and nothing else

- **Statement.** A navigation to the declared policy address returns the policy document rather than the app shell, and that visit is inert in four separate ways: the page **runs no script**, it **fetches nothing from a third party**, it **registers no service worker**, and it **does not overwrite the app shell's offline copy**. All four hold for both spellings the address answers — the route `/privacy` and the file `/privacy.html` — because the worker's fetch handler compares `url.pathname` and a page reachable under two names is two pages to it. The document also links nowhere: it carries no `<a>` at all, and the URLs it cites, including the four third-party policies, are `<code>` rather than navigation.
- **Enforced by.** **The runtime half, and it is the half that carries the claim** — `app/tests/privacy-surface.spec.js` in the `parity` job's `behavior` project **on every push**: a real browser navigates to the address and the document is what renders (`the app shell` would be the defect, and was the shipped behaviour before PPR-P1, since `app/nginx.conf` had one catch-all); the network log for that navigation contains no script, no stylesheet and no third-party request; `navigator.serviceWorker.getRegistrations()` is empty after it; and the app shell's cached offline copy is read back **after** a visit under each spelling and must still be the shell. **The static half** — `app/tests/privacy-page.spec.js` in the `contract` project on every push: the page is in `app/Dockerfile`'s COPY list, is **not** in `OFFLINE_URLS`, contains none of `<script` / `rel="stylesheet"` / `rel="modulepreload"` / `rel="manifest"` / `<a ` / `/m/` / `{{`, declares a language and a viewport, and asks no robot to forget it. Comments are stripped before matching, so the page can explain in its own head why it carries no script without the explanation reading as one.
- **The two halves are named apart on purpose (`AGENTS.md` §11).** The static half reads the tree — the admissible kind for an absence — and cannot carry the runtime claim: a page can contain no `<script` and still be poisoned into the shell's cache entry by a worker rule written elsewhere. That is exactly the defect `DIA-DL-005` (m) paid for once, with `/transfer.html` as its first page, and the reason the regression leg exists at all.
- **Soundness measured, not argued.** Removing `'/privacy'` from `NON_SHELL_PAGES` in `app/sw.js` reds the offline-copy leg with `Expected: "shell" / Received: "poisoned"`. Run and reverted at PPR-P1.
- **Observed.** On every push since PPR-P1, in the `parity` job. Locally at PPR-P3, inside `contract` + `behavior` **1336 passed / 0 failed / 0 skipped** in the pinned container.
- **Landed in.** PPR-P1.
- **Scope.** Covers what the **repository's** server mirror serves and what a real browser does with it. It does **not** cover production nginx: nothing here runs the real image, the parity suite drives `app/tests/server.js`, and what pairs the two is the delivery drift guard plus the owner's `curl` smoke against the tagged revision (`docs/RUNBOOK.md` § Promotion + rollback, step 3). It says nothing about the CONTENT of the document — that is the owner's text, and only its structural correspondence with `docs/privacy-policy-v1.0.md` is asserted, heading by heading and on both statements of the effective date. It says nothing about whether the address is reachable from outside, un-geo-blocked, or indexable, which ADR-050 §5 needs and no test can see.

### PPR-P2-INV-001 — Nothing reaches an analytics origin before an explicit yes, and withdrawal returns to that state

- **Statement.** On the web channel no request reaches an analytics origin and no GA4 configuration runs until the visitor has explicitly consented. Before an answer exists the tag is not loaded, `gtag` is not configured and `trackEvent` is a no-op — not a queue, not a deferred send. A banner offers acceptance and refusal as **two actions of equal weight**, and refusal is reachable in one action. Consent is withdrawable at any time through the «Cookie» control in the site footer, and after withdrawal nothing further is sent. The native channel carries no analytics at all and this invariant has no branch for it.
- **Enforced by.** `app/tests/consent-surface.spec.js` in the `parity` job's `behavior` project **on every push** — a real browser, the shipped `/m/v8/` modules, and the network log as the instrument rather than a spy on our own wrapper: the assertion is that no request leaves for the analytics origin, which is true of a tag that never loads and false of one that loads and is told to be quiet. `app/tests/consent-gate.spec.js` drives the gate's decision surface in the `contract` project.
- **This is what makes an accepted deviation checkable rather than remembered.** `PDR-019` accepted "GA4 without consent" for the dark-build period. That deviation ends with this milestone, and an accepted deviation with no detector is an intention (`AGENTS.md` §11); this entry is the detector.
- **The fixture hazard that would have emptied the suite, closed rather than noted.** The gate makes `trackEvent` a no-op for anyone who has not consented, so fourteen `trackEvent` call sites asserted through `window.dataLayer` elsewhere in the suite would have gone silently vacuous against a fixture with no answer stored. The seeded states carry `granted` for that reason; `STATES.firstRun` deliberately carries none, because that is what a first visit is, and the consent spec seeds its own states either way (`PPR-DL-002` (s)).
- **Observed.** Local, 2026-08-23 — `behavior` **111 passed** at PPR-P2, and **1336 passed / 0 failed / 0 skipped** across `contract` + `behavior` at PPR-P3 in the pinned container. **Not yet observed on CI**: `parity` runs on every push, and no push of this branch has happened yet — the discharging run is the milestone PR's own.
- **Landed in.** PPR-P2.
- **Scope.** Covers the **web** channel, the shipped `/m/v8/` generation, and the origins named in the consent configuration. It says nothing about what Google does with an event once one is legitimately sent, nothing about any analytics surface a later mount generation might add — a frozen generation is not a second declaration and is measured against its own taxonomy (`PPR-DL-002` (o)) — and nothing about the storage of the answer beyond the fact that the gate reads it: where consent is recorded and for how long is `A3-DL-003` debt 2's subject, not this entry's. It is not a claim about the legal sufficiency of the banner's wording, which is the owner's text.

### PPR-P2-INV-002 — The download is offered only to a visitor whose platform can act on it

- **Statement.** The APK download control is revealed only to a visitor on a platform that can install one, and a platform the app cannot read is offered nothing. The probe is `surfaces/channel.js isAndroidPlatform()` against `CHANNEL_CONFIG.androidPlatformToken`, matched case-insensitively as a substring, and it fails **closed**: an absent `navigator`, an absent user-agent string and any unrecognised platform all return false, and false means the honest sentence instead of a file the visitor cannot use. This condition is **additional** to the release declaration, not a replacement for it — no declared release, no offer, whatever the platform.
- **Enforced by.** `app/tests/channel-composition.spec.js` for the executing half and `app/tests/consent-gate.spec.js` for the decision surface, both in the `parity` job **on every push**. The token is read out of the knob source rather than re-typed, so a knob change cannot leave the guard testing a string nothing ships.
- **Detection is a heuristic, and is written down as one.** What this protects against is a broken offer — a download button on a desktop — not a determined visitor, who still has the release page. Widening the token to a list of platforms would widen the set of visitors handed a file, which is the direction that has to stay hard (`PPR-DL-002`).
- **Observed.** Local, 2026-08-23 — inside `behavior` **111 passed** at PPR-P2 and `contract` + `behavior` **1336 passed** at PPR-P3. **Not yet observed on CI**, for the same reason as `PPR-P2-INV-001`: no push of this branch has happened yet.
- **Landed in.** PPR-P2.
- **Scope.** Covers **whether the control is revealed**, on the shipped generation, for the platforms a user-agent string can express. It says nothing about whether the release the declaration names actually exists — that is `DIA-P2-INV-002`'s subject and remains an owner statement — nothing about the integrity of any APK (`RSN-P2-INV-001`), and nothing about the control's LABEL, which still reads «Скачать APK» on a desktop where nothing is downloadable and is carried as debt rather than fixed here.

## Entry format (for future entries)

- **Id.** `M{N}-P{k}-INV-{NNN}` — `N` is the milestone number, `k` is the packet number within the milestone, `NNN` is zero-padded sequence within the packet (`001`, `002`, …).
- **Required fields.**
  - **Statement.** The invariant in one sentence.
  - **Enforced by.** File path(s) of the enforcing artifact — test, lint rule, schema constraint, runtime guard, or CI workflow.
  - **Landed in.** Packet id + commit SHA where enforcement was introduced.
  - **Scope.** What the invariant covers, and explicitly what it does not.
