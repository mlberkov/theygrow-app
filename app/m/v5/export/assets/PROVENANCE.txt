Vendored binary assets for the export print layer (L1-P3, LSC-DL-003).

Both files are pinned by SHA-256 in app/tests/export-contour.spec.js. A changed
byte reds that gate; these are the only binaries this app ships that are not
icons, and they end up inside every artifact a family exports, so they are
treated as a supply-chain surface rather than as content.

WHY THEY EXIST AT ALL. PDF/A requires every font used to be EMBEDDED, and there
is no Cyrillic font among the PDF base-14. So any PDF this product emits — /A
conformant or not — has to carry a font with it. The ICC profile is required by
PDF/A-2b's OutputIntent, which is what makes the file's colour reproducible
without reference to the device that wrote it.

            permitted use; redistribution of the font file requires the licence
            to travel with it, which is why PTSans-OFL.txt is committed here and
            shipped alongside.
    why     Designed for Cyrillic, which is the family's language. Vendored
            UNMODIFIED: the upstream bytes are what the hash pins, so provenance
            is checkable against the source rather than against a local edit.
            It is larger than this packet estimated when planning (~443 KB
            against an assumed ~120 KB) because the upstream web build carries
            `kern` (144 KB) and `hdmx` (34 KB) tables the PDF writer never uses.
            Stripping them would save roughly 200 KB but would mean the shipped
            file is no longer the file the hash can be checked against upstream,
            and a hand-rolled table-directory rewrite is a new class of defect
            for a saving that costs the web channel nothing (see the precache
            note in app/sw.js).

    why     PDF/A-2b needs an OutputIntent with an embedded destination profile.

            into every exported artifact, so its size is paid per export.
